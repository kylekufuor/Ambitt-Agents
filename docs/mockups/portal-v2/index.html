Rendered by the layout, never unmounts

  • The 248px rail, including every count and status word in it
  • The 52px context strip and the breadcrumb inside it
  • The account chip and the help link
  • The content column's max width, so density cannot drift per page

Today PortalShell is rendered by each page.tsx, so every navigation unmounts the rail and the route's skeleton draws a centred top bar where the rail was. That is the single worst thing about the portal and it is fixed by moving four elements up one level.

Rendered by the page, swaps on navigation

  • The page title and its one primary action
  • The content, and the content's skeleton
  • Filters, which live in the query string so back removes one at a time
  • Nothing else. If it is the same on two routes, it belongs in the layout.

The breadcrumb is derived from the route, not from data, which is why it can render before the page does. That is the whole reason it sits in the strip and not in the page body.

Deciding an item does not navigate. The page stays where it is and the count above updates, so going back never shows you a decision you already made as still pending.

Why four verbs and not two. Approve and dismiss forces a client who wants one sentence changed into a dismiss, and we lose both the email and the reason. Edit captures the correction and turns it into training; Respond captures the reason without touching the letter. Accept is the only filled button on the row, Ignore is the only one set apart, and there is no "approve all six" on this page: one tap that sends six emails in Casey's name is exactly how you earn the phone call that starts "I did not know it sent that."

Navigation rules. These are the ones that are easy to break by accident.

  • The shell is rendered by the layout. No page renders it, and it must not unmount on any client side navigation.
  • The rail is always expanded on desktop. Never collapsed by default, never hover to expand. A user chosen collapse is fine; a default one is not.
  • Two levels, and no more. Account level, then agent level. Anything deeper belongs to a page, reached by a section index on that page.
  • Every destination is a route. No hash anchors in navigation, ever. If it cannot hold an active state it is not a destination.
  • Breadcrumbs only, and the word "Back" never appears. Browser back handles history, the breadcrumb handles hierarchy, and naming them differently is what stops clients confusing them.
  • The breadcrumb lives in the strip, derived from the route only, never from a referrer or a from parameter. It renders identically for a client who clicked through and one who arrived from an email.
  • Status in the rail needs a word, not only a colour, and two different states never share a colour.
  • List state lives in the URL. Typing replaces, committing a filter pushes, so back removes one filter at a time and support can say "open this link".
  • Actions do not navigate. Approve, save, connect, pause: all stay on the screen and revalidate in place. The only exception is advancing inside the approvals queue, which replaces rather than pushes.
  • Back is never undo, and back never shows a decision you already made as still pending.
  • A destination that can only ever be empty is not in the rail, but the route still renders a crafted empty state so old email links keep working.
  • Only the content column skeletonises, and the skeleton is the shape of the page that is coming.

Taken, and left behind

Taken

  • Databricks: the pinned expanded rail, one accent in one placement, DM Sans at 400 and 500, DM Mono for every eyebrow, timestamp and numeral, and the discipline of showing a locked item rather than hiding it.
  • HubSpot: one record scaffold reused on every surface, a real global strip separate from navigation, and higher contrast status badges.
  • Lev: the oversight contract named in the client's language, as three actual blocks on a record, plus a breadcrumb on every page below the top.

Left behind

  • Databricks: the 20px card radius and the 60px display type. Both are marketing values, and rounded everything is a named tell.
  • HubSpot: collapse by default with hover to expand, fourteen primary categories, and 300 weight body, which fails our contrast floor on a warm ground.
  • Lev: the numbered 01 / 02 / 03 section markers and the credit metering language.
  • Everyone: a command palette. It earns its keep past ten features and we have six per agent.

Fonts are self hosted from this folder. DM Sans variable and DM Mono, copied from client-portal/public/fonts with their licences. No CDN link anywhere: a silent fallback to a system face is the one failure nobody files a bug for, and the product just quietly looks cheap.
